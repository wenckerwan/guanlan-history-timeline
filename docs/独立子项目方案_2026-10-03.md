# 近现代史时间实验室：独立子项目方案（待审核）

## 1. 项目定位

暂定名称：近现代史时间实验室。定位为交互式历史学习应用，独立开发、运行、部署与设计前端；后续通过组件和数据适配层接入观澜。当前仅制定方案，不搭建或改动观澜。

工程根目录：`D:\code_files\考研政治工程文件\近现代史时间轴`。资料输出目录：`F:\2027考研资料\考研政治\近现代史时间轴`。遵循资料工作区README：源码、设计文档、构建产物、数据库、派生JSON、测试及截图日志全部放工程目录，资料工作区仅保留学习文档和明确交付的学习成品。

本轮读取的观澜候选接入工程：`D:\code_files\观澜｜考研政治知识库\guanlan`。其README及前端package.json表明前端为Nuxt 3/Vue 3；设计文档记录Hyperf `/api/v1`、`{data: ...}`包络、camelCase字段及账号/收藏/笔记/答题记录。属于本地代码与文档证据，不代表已验证线上部署及全部接口状态。接入前重新确认目标分支、真实接口和账号规则。

## 2. 技术选型

推荐Vue 3 + TypeScript + Vite，搭配Vue Router与小规模状态管理。先做独立浏览器应用，保留将历史探索主界面导出为Vue组件的能力；宿主需跨框架时，再评估Web Component。不预先建立复杂微前端平台。

备选：独立Nuxt应用，适合需要服务端页面渲染时；React应用，适合后续存在明确React团队要求时。当前首选Vue/Vite，因为时间轴主要是浏览器交互，并且与观澜Vue生态兼容。

时间轴用SVG绘制刻度、时间范围、轨道和关系线；文字、卡片和面板用HTML，避免全部画在Canvas导致选择文本与键盘访问困难。数据量增大后再按实际性能引入可视区渲染。

首版数据为经校验、有版本号的静态数据包；本地学习状态存IndexedDB。首版不自建第二套账号系统。界面通过Repository接口读写，分别提供LocalRepository与未来的GuanlanRepository。

生产构建与部署资料都放工程目录。浏览器应用支持本地服务及独立静态部署，不再要求双击单HTML。离线能力先覆盖已加载的核心事件数据和本地学习记录；PDF未缓存时明确标注原页暂不可用。

## 3. 新前端设计

视觉方向：现代历史档案馆。深海军蓝导航、暖白阅读画布、铜金定位标记，配少量区分主题的辅助色。避免把全页做成暗色或堆满大卡片。中文标题使用本地可用宋体，正文使用清晰的系统黑体，日期使用等宽数字。独立设计令牌、组件及样式命名空间，不依赖观澜主题。

三种可选方向：现代档案馆（推荐，适合长时间阅读和证据核查）；深色时间控制台（沉浸感强，但小字与长阅读需要额外照顾）；书页式叙事展览（适合导览，但横向比较效率较低）。

桌面布局：

- 左侧窄导航：探索、对照、练习、我的学习。
- 中央主画布：同步时间轴与主题轨道。
- 顶部：搜索、时期定位、主题筛选、缩放与布局切换。
- 右侧可收起面板：事件原文、两种来源的日期、页码、对比操作。
- 底部：全史缩略轴与可拖动的时间窗口。

初次打开直接进入探索页，显示当前1839—2009范围及适量代表节点；2009年后的扩展须内容审核，不因新应用结构自动加入。手机端改为纵向时间窗口与单主题浏览，详情使用底部面板，保留按钮式缩放和年份跳转。

## 4. 交互设计

### 时间窗口

总览、十年、年三级缩放；选中事件后切换尺度保持该事件在视野中。事件密集时按时段聚合，展开显示成员。提供拖动、缩放按钮与年份跳转，手势不作为唯一入口。

日期精度必须直接决定绘图：只有年份的事件显示为全年范围，只有月份的显示为月范围；时段事件显示区间。日期范围只是视觉表达，不把1月1日写成史实。未知日期放入明确的未定位分组。

### 同期观察

主题轨道拟包括革命与战争、思想与著作、政治制度、经济与社会；具体事件归类需校验。选择某年或某时间窗口，所有轨道同步定位；用于发现同一时期的不同事项。用户主动选择时才显示关联线；关联说明及新增事实仍先审核，不能把同期关系画成因果关系。

### 事件比较

支持选中2—3项，按时间、原文与审核通过的备注并排比较。比较状态可通过事件ID和筛选条件形成可恢复的链接。人物和会议标签提供快捷筛选。

### 来源对照

延续用户要求：日期对照区域只列教材时间与原PDF时间，每个时间后紧跟来源名称和PDF页码链接。默认日期依据为《中国近现代史纲要》（2023版）；原PDF日期另存，永不覆写。

未在教材找到可靠定位时，不显示为教材已确认；原表未列的事项明确显示未单列。对照区域不恢复冗长纠错说明。PDF页码与教材印刷页码分开建模，不混用。

### 主动回忆

首版提供先后排序与隐藏日期回忆。只有已经确认的时间参与判分；同年、同月或范围重叠且无法确定先后的事件允许并列，不制造唯一顺序。可在反馈后打开来源。错题只代表当前用户作答，不影响史实数据。

### 我的学习

保存书签、个人笔记、上次时间窗口、练习记录。提供明确的本地保存提示与备份导出。接入观澜后，再根据服务端规则确认哪些记录同步；本地记录合并需要去重和冲突策略。

## 5. 数据整理

124组原表不是124个独立事件。先建立原表组与子事件的对应关系；合并单元格不得按行数自动配日期。每个事件拥有稳定ID。

内容模型：Event、DateAssertion、Citation、Topic、ReviewedRelation。日期断言保留来源、原始时间文字、可排序起止范围、精度、历法与审核状态；引用保留documentId、版本、PDF页码、原表定位及可核对文本。

学习模型：Bookmark、PersonalNote、Attempt、ViewState。学习状态独立于教材内容版本。内容发布使用明确的已审核状态，待审核的增补数据不会出现在正式学习视图或训练答案中。

原PDF只读备份、34项对照数据及当前Obsidian笔记保留。日期纠错和新事项的采用仍须按用户审核结果发布；本轮接受应用方案不等于接受所有史实补充。

## 6. 后续接入观澜

独立模式：数据包 → LocalRepository → 历史探索组件 → 本地学习存储。

接入模式：观澜内容/用户接口 → GuanlanRepository → 同一历史探索组件。

接入路径优先为两步：先在观澜设置入口、跳转独立应用的具体事件；再按需要将探索组件嵌入观澜的历史学习路由。两种方式保留独立主题，不要求重做UI。

观澜需明确或扩展的内容：历史事件和日期断言的接口、文件documentId到原页的访问方式、事件收藏/笔记目标类型、练习记录类型、账号上下文与权限检查。现有文档中的收藏目标列表不包含历史事件，不能假定零改动即可复用。

不把F盘/D盘路径放入线上接口；通过文档标识解析引用。登录凭证不通过URL传递，不由子项目另行索取密码。只读探索可独立工作，账号态在明确接入合同后启用。

## 8. 分期与验收

1. 新界面原型：完成探索页、来源面板、比较区和练习页的交互原型，先验证桌面与手机导航。
2. 数据与探索首版：校验原表拆分和日期精度，交付可独立启动的应用、缩放、主题轨道、同期定位和来源对照。
3. 学习首版：加入日期回忆、排序练习、书签和本地学习记录，验证保存与恢复。
4. 观澜接入：确认宿主版本和接口后，做适配器、账号记录同步及嵌入验收。

验收重点：日期与来源完整、模糊日期无伪精度、密集事件可读、缩放保持焦点、键盘替代拖动、手机不溢出、待审内容不进入答案、学习记录可靠恢复、独立模式不依赖观澜运行。接入阶段另验文档引用、身份权限、账号数据隔离及同步冲突。

本方案待用户审核，尚未新建应用脚手架、安装依赖或改动观澜。
